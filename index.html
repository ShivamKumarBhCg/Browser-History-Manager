DSA Concepts Used

Stack (LIFO)

A linear data structure where elements are added and removed from the same end (top). Used for Back and Forward navigation — just like a real browser.

Push: O(1)Pop: O(1)Peek: O(1)

Doubly Linked List

Each node has a pointer to both its previous and next node. Maintains the complete history timeline with O(1) insertion and efficient bidirectional traversal.

Insert: O(1)Delete: O(n)Search: O(n)

HashMap

Key-value store with O(1) average lookup. Uses a polynomial hash function and separate chaining to handle collisions. Stores URL metadata for instant search.

Get: O(1) avgSet: O(1) avgDelete: O(1) avg

Project Presentation Summary

Objective: Implement and demonstrate Stack, Doubly Linked List, and HashMap through a functional browser history simulation.

Stack Application: Back navigation uses a stack (LIFO). Visiting a new page pushes the current page; clicking Back pops from the Back Stack and pushes to the Forward Stack.

Linked List Application: Every visited URL is stored as a node in a doubly linked list, maintaining a complete chronological history with O(1) insertion. Nodes can be traversed forward (oldest→newest) or backward (newest→oldest).

HashMap Application: Each URL maps to its metadata (title, visit count, last visited). The custom hash function distributes keys across 53 buckets with separate chaining for collision handling, giving O(1) average search time.

Key Insight: These three structures complement each other — the HashMap provides O(1) lookup, the Linked List maintains order, and the Stacks manage navigation state — mirroring how real browsers work internally.
